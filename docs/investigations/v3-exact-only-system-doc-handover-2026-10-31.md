## Decisions required before implementation

1. **Exact format:** accept or reject exact schema `2` and a new exact-leaf format identity (candidate `exact-timeseries-leaf-v2`), define parent/leaf payload and artifact kind strings, canonical serialization/hash algorithm and every required/forbidden field. These are candidates, not selected constants. Keep schema-1 records readable under their original aligned dependencies.
2. **Selector and keys:** retain the deterministic scoped manifest as the explicit selector. Define deterministic new leaf keys that do not overwrite selected schema-1 dependencies during conversion. Specify validation of revisions within the configured root, selector old-identity guards, retry/read races and same-format corrections. Prevent key/body digest self-reference if addressing by digest. Preserve unchanged-leaf byte stability and bounded continuation without a second permanent index service/tree. Explicitly distinguish a short fail-closed canonical-source race from an inconsistent partially converted scope becoming selectable.
3. **Direct canonical descriptor:** define the parent field name and exact key/body SHA/byte size/`manifest_hash`, DCP identity, count, versioned logical hash metadata, complete timeseries counts/membership and file/layout evidence. New schema must reject aligned links as authority. Keep complete DCP identity in the parent/prerequisite, not every leaf, so an unrelated canonical change need not churn unchanged leaf bytes.
4. **Full proof and lifetime:** specify root-to-pollutant chain/alias authentication, full parent/leaf/member/per-file reconciliation, positive counts/totals/bounds, exact group coverage/order and actual projected ranges. Define which authenticated writer layout evidence may be reused, by whom, and for how long under continuous lock/file identity. Absent trusted proof requires offline actual-file inspection. A second generated JSON structure or a logical digest alone is not physical-layout proof. Retain required independent complete-file decode/value/hash checks at their existing boundaries.
5. **Publication and completed hierarchy:** specify the new dependency graph and its final acceptance phase without contradicting bottom-up canonical publication. Existing-scope conversion can authenticate the completed root before building; new writers must reconcile the completed new root before claiming final success/deletion eligibility. Retain canonical-before-dependent-object ordering and durability; do not impose a future root before creating its children. Define repair of selector-selected/latest-unfinalised interruption without silently repinning older migration evidence.
6. **Mixed formats and resource bounds:** allow old/new scopes in selected v3, require one supported format per authenticated scope, per-scope format pinning in caches/cursors and explicit stale cursor rejection. Decide whether a new private cursor version is needed. Current reader implementation already uses cursor **3** for physical-schema 3/4 support; do not reuse cursor 3 for incompatible new fields by assumption. Preserve the file SHA/size/required ETag gate and all existing read/metadata/range/page/row/CPU limits. No extra chart-time hierarchy walk or footer discovery.
7. **Index-only conversion/recovery:** add authority for a deterministic finite scope/byte/object-bounded derived-index conversion within selected v3 without rewriting canonical observations. Pin prepared bytes, original/current source and selectors, exact progress/readiness evidence and restart semantics under existing exclusion. Require capacity admission, current-data rollback, retained legacy objects and a separately authorised retirement stage. Existing `v3-rebuild` canonical migration is not this operation.
8. **Publication cessation gate:** reconcile the proposal's §6 new-schema aligned-node removal with §11 collective acceptance before stopping aligned production. State precisely whether a controlled new-format TEST scope may omit aligned production to establish acceptance and what prerequisites admit it; no blanket cessation before consumer closure. Continue all schema-1 dependencies. Execution still requires separate deployment/publication authorisation.

## Proof-equivalence acceptance checklist

The accepted replacement must assign each proof to the appropriate writer, verifier, rebuild or reader boundary:

| Existing evidence | New-schema proof that must replace it |
| --- | --- |
| Aligned parent → canonical pollutant | Direct exact parent → actual completed-root-authenticated pollutant key/body SHA/size/manifest hash/scope/count/versioned logical hash. |
| Aligned shards → complete series/count/file set | Entire exact member/leaf set reconciled to complete canonical DCP and per-file counts, not only the requested leaf. |
| Aligned/leaf segment comparisons | Expected segments reconstructed from pinned actual Parquet layout or explicitly authenticated trusted writer evidence; account for all groups once and compare offsets, sizes, dictionaries, pages, order and bounds. |
| Source-to-final logical equality and independent stored-value checks | Preserve existing complete lossless decode/recompute obligations using the applicable hash version and duplicate multiplicity. File SHA or footer agreement is insufficient by itself. |
| Current indexed physical file | Unchanged runtime SHA/size/required current ETag validation and conditional bounded reads. |
| Complete scoped authority | Non-colliding leaf dependencies, explicit supported selector, fail-closed currentness, bottom-up durable publication and interruption recovery. |

No blanket “proof equivalent” claim is justified before this assignment and implementation. JSONgen's inspector must not independently inspect Parquet to compensate for missing writer/layout evidence; that conflict would require a further explicit decision rather than weakening either contract.
