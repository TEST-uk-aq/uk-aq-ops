# TEST station-history CPU investigation (12 October 2026)

## Executive summary

`/v1/station-series` has substantially more work than an observation-only history read. The supplied Cloudflare export (5–12 October, 1,297 invocations) reports 15 ms median CPU for station-series versus 4 ms for observation-history, and 17 ms versus 5 ms within station-series with AQI on versus off. These are request cohorts, not controlled CPU attribution. The two matched station-series groups suggest 5–6 ms incremental CPU, but cannot establish a population effect. There is no evidence that breakpoint arithmetic alone costs 12 ms. The likely cost is a combination of additional PM context reads, row parsing/copying/sorting, hourly grouping and gap-grid expansion, rolling-window preparation, continuity lookups, diagnostics and response serialisation. R2/DB *waiting* mainly increases wall time; decoding their JSON and iterating returned rows consumes CPU.

The smallest useful improvement is to make the calculated path perform one canonical R2-first merge and one hourly preparation, then call the existing shared AQI helper over the bounded visible interval plus at most 23 preceding PM hours. It should not recreate a second AQI algorithm. Correct the calculated path's conflicting-overlap handling and the completeness/cache treatment of legitimately blank AQI hours as part of that work. JSONgen, when separately activated, moves historical AQI calculation out of request time; the Worker still needs the short recent IngestDB calculation and a correct cross-boundary PM context. This is a future design, not current default TEST serving.

## Current `/v1/station-series` processing

1. **Parse and resolve identity.** GET, `format=objects`, timeseries, pollutant, UTC bounds and part flags are validated. Both parts default on; PM AQI adds 23 context hours ([index](../../workers/uk_aq_station_history/src/index.mjs#L100-L129), [route](../../workers/uk_aq_station_history/src/index.mjs#L788-L806)). The feature path resolves the R2 timeseries binding and continuity family; the legacy path resolves authoritative identity through a Supabase `timeseries` query ([continuity](../../workers/uk_aq_station_history/src/continuity.mjs#L72-L86), [identity](../../workers/uk_aq_station_history/src/identity.mjs#L40-L114)). The binding is date-valid, and member segments cover visible and context intervals ([continuity](../../workers/uk_aq_station_history/src/continuity.mjs#L89-L112)).
2. **Bound the head and query IngestDB.** With calculated history enabled, a combined observation/AQI station-series response takes the later of its two head starts; defaults give at most seven visible days (168 hours), even for a 31/90-day chart. PM reads up to 23 more hours. An RPC is called for each selected continuity segment; the RPC uses a `12h`, `24h`, `7d` or `30d` *label*, `include_status:false`, then parses, normalises, deduplicates and filters locally ([feature path](../../workers/uk_aq_station_history/src/index.mjs#L593-L629), [RPC](../../workers/uk_aq_station_history/src/ingest_observations.mjs#L68-L73), [request/parse](../../workers/uk_aq_station_history/src/ingest_observations.mjs#L235-L355)). The label can fetch more recent rows than the precise needed interval; CPU is spent parsing/normalising them before filtering. Verification status is not fetched or considered by this RPC path.
3. **Read canonical R2 observations.** The calculated path reads each physical member's selected-generation exact observations for the visible interval plus context ([calculated history](../../workers/uk_aq_station_history/src/calculated_history.mjs#L160-L213)). Selected v3 divides requests by UTC day and walks bounded physical pages (16 pages and the common row budget); each response JSON is parsed and rows checked/normalised ([R2 reader](../../workers/uk_aq_station_history/src/r2_observations.mjs#L273-L368)). v2 has a one-request path ([same reader](../../workers/uk_aq_station_history/src/r2_observations.mjs#L252-L270)). The R2 reader Worker may do Parquet decoding, but that CPU belongs to a **different invocation**, not this station-history CPU metric.
4. **Merge and calculate.** The calculated path copies and sorts R2 and ingest rows, looks up a continuity member for each row, builds visible rows, maps the logical family to the requested identity for calculation, aggregates readings into hourly means, pivots to helper rows, inserts synthetic missing PM hours, computes rolling means and count, converts each helper row to both DAQI and European AQI, filters the visible endpoints and restores physical member identity ([merge](../../workers/uk_aq_station_history/src/calculated_history.mjs#L27-L56), [aggregation/calculate](../../workers/uk_aq_station_history/src/calculated_history.mjs#L59-L150), [shared helper](../../lib/aqi/aqi_levels.mjs#L322-L439), [indices](../../lib/aqi/aqi_levels.mjs#L459-L557)). NO2 DAQI and European AQI use the same hourly mean; PM European AQI uses the hourly mean, while PM DAQI needs the rolling 24-hour mean and at least 18 valid hours ([AQI contract](https://github.com/TEST-uk-aq/uk-aq-system-docs/blob/main/system_docs/aqi-levels/contract.md)).
5. **Completeness, validation, response and cache.** The Worker scans expected hours, source completeness and AQI statuses, builds gap arrays/source counts/segments, then stringifies the full JSON body ([calculated history](../../workers/uk_aq_station_history/src/calculated_history.mjs#L218-L316), [route](../../workers/uk_aq_station_history/src/index.mjs#L810-L822)). Optional validation is scheduled with `ctx.waitUntil`; when actually run and comparable, it reads retired R2 AQI and compares rows, adding invocation CPU after the response is built ([validator](../../workers/uk_aq_station_history/src/aqi_validation.mjs#L55-L85)). The Worker gives complete station-series responses a 60-second cache header; partial responses use `no-store`. The cache proxy normalises part flags in keys, checks Cache API before calling the Worker, and caches only complete gap-free payloads; its stale-cache feature and TTL are separately flagged ([cache keys](../../workers/uk_aq_cache_proxy/src/station_history/cache_keys.mjs#L26-L55), [proxy lookup](../../workers/uk_aq_cache_proxy/src/index.ts#L3177-L3212), [cache inspection](../../workers/uk_aq_cache_proxy/src/station_history/stale_cache.mjs#L105-L168)). Proxy parsing/cache work is **proxy CPU**, not station-history CPU. Cache hits avoid a station-history invocation entirely.

If calculated history is **disabled**, an AQI request uses the older path: IngestDB capability check, stored R2 AQI head fetch on fallback, R2 observation fetch, R2-first observation merge, duplicate normalisation, shared calculation of R2-missing AQI hours, then stable-head merge ([index](../../workers/uk_aq_station_history/src/index.mjs#L413-L579)). If continuity alone is enabled, calculated observations are built and then the legacy AQI branch runs as well ([index](../../workers/uk_aq_station_history/src/index.mjs#L618-L655)); that is genuine duplicate work and should be investigated only if current settings select it. The old `/v1/aqi-history` code also remains, but source presence does not prove active normal-chart use.

### AQI-only work and scaling

| Requested window | Calculated station-series visible work with defaults | PM source interval | Important qualification |
| --- | ---: | ---: | --- |
| 1 hour | 1 endpoint | up to 24 hours | Context can dominate useful output. |
| 24 hours | 24 endpoints | up to 47 hours | Includes 23 preceding endpoints. |
| 7 days | up to 168 endpoints | up to 191 hours | May also include duplicate/source rows within hours. |
| 31 days | initial response up to 168 endpoints | up to 191 hours | Older data uses up to 7-day combined chunks; total chart cost spans multiple invocations. |
| 90 days | initial response up to 168 endpoints | up to 191 hours | Same cap; approximately 12 older 7-day chunks for full coverage, depending on range/settlement. |

The caps are defaults and can be overridden within [policy bounds](../../workers/uk_aq_station_history/src/policy.mjs#L34-L46). Chunk requests cap combined observation history at seven days ([chunk parser](../../workers/uk_aq_station_history/src/history_chunks.mjs#L35-L66)); they run calculated history when its flag is on ([chunk route](../../workers/uk_aq_station_history/src/index.mjs#L696-L747)). Thus the supplied 31/90-day station-series medians should not be read as a single invocation calculating 31/90 days. A larger chart increases **number of requests and aggregate CPU**. Repeated 23-hour context at each chunk boundary is real but bounded.

## Most likely CPU costs and correctness findings

| Finding | Evidence and interpretation | Confidence |
| --- | --- | --- |
| AQI raises work mainly through preparation, not index lookups | Merge copies/sorts; hourly grouping; helper pivot and sorting; PM grid; for each endpoint rolling code scans up to 24 prior rows and builds two arrays, including the unused PM pollutant array; final row conversion and sorting ([calculated history](../../workers/uk_aq_station_history/src/calculated_history.mjs#L33-L150), [helper](../../lib/aqi/aqi_levels.mjs#L371-L439)). Breakpoint lookup is over a handful of bands ([helper](../../lib/aqi/aqi_levels.mjs#L459-L517)). This explains plausible millisecond overhead but does not quantify it. | High for operations; medium for ranking. |
| Repeated work within a request | Already sorted ingest rows are sorted again after merge; `memberAt` calls segment selection/sort per observation and again per AQI output; repeated date parse/ISO formatting, `.map/.filter` arrays, gap scans and source-count filters occur ([ingest](../../workers/uk_aq_station_history/src/ingest_observations.mjs#L198-L201), [merge](../../workers/uk_aq_station_history/src/calculated_history.mjs#L27-L56), [completion](../../workers/uk_aq_station_history/src/calculated_history.mjs#L218-L315)). The feature path does **one** hourly aggregation for the calculated result, not a proven duplicate aggregation; the legacy-continuity combination can add an independent second processing path. | High. |
| R2/ingest boundary can fail on an ordinary correction | `mergePhysicalObservations` throws when the same timestamp has a different value before the R2 row can replace ingest ([merge](../../workers/uk_aq_station_history/src/calculated_history.mjs#L33-L56)). The active contract says committed R2 wins exact physical overlaps. The older shared merge does this without the conflict throw ([helper](../../lib/aqi/aqi_levels.mjs#L610-L630)). A changed value can therefore produce 502 instead of R2 precedence. Check identity conflicts separately; do not silently accept cross-identity overlap. | High code finding; occurrence in 166 reported 502s unproven. |
| Normal blank AQI may prevent caching | `aqiStatusesComplete` requires every returned row to have both statuses `ok`; `insufficient_samples` or `missing_input` makes the response incomplete ([calculated history](../../workers/uk_aq_station_history/src/calculated_history.mjs#L240-L259)). The AQI contract says a correctly evaluated blank hour is valid output, and the proxy caches only complete gap-free responses. This can repeat full CPU work for sparse PM series, though cache freshness must still protect mutable recent observations. | High code/contract mismatch; traffic effect unmeasured. |
| Validation may add extra CPU and deprecated dependency | Validation reads/stores/computes comparison maps on eligible sampled/all requests, potentially after response via `waitUntil` ([validator](../../workers/uk_aq_station_history/src/aqi_validation.mjs#L55-L85)). `missing_in_r2` is expected under the retired persisted-AQI model and does not itself prove AQI error. Exact CPU impact and current sampling rate unknown. | High path finding; low CPU attribution. |
| Ingest RPC overfetch and JSON payload | The labelled RPC has no `since_ts` and no row limit; filtering happens after JSON parse and normalisation ([RPC](../../workers/uk_aq_station_history/src/ingest_observations.mjs#L240-L247), [parse/filter](../../workers/uk_aq_station_history/src/ingest_observations.mjs#L282-L355)). For a 1-hour request it may still process 12–24 hours or more. This is shared with observation-only requests; AQI context may select a longer label. | High path finding; magnitude unknown. |

The principal cause is **F: a combination**, weighted toward B (hourly/rolling preparation) and C (row merge/parse), with D (continuity/validation) and E (response/diagnostics) contributing. A (breakpoint mathematics) is unlikely to dominate. Network round trips and R2 reads have important latency/cost effects but should not be equated with CPU. The exported medians cannot separate these operations, and the 502 cluster (7–9 October) could reflect upstream failures, identity/merge conflicts or deployment changes; no error-code distribution was provided to attribute it.

## Recent IngestDB AQI and the JSONgen seam

For a recent NO2 endpoint, use eligible observations in its one represented hour, aggregate once, then the shared helper produces hourly DAQI and European AQI. For a recent PM endpoint `n`, only observations at endpoints `n-23` through `n` can influence its DAQI; its European AQI needs the current hourly mean. For an output interval `(S,E]`, one bounded source interval from `S-23h` through `E` is sufficient for PM, including context that crosses the committed R2 / mutable IngestDB boundary or a date-valid continuity member change. There is no mathematical need to recalculate older published AQI hours when recent observations only fill later hours. Do not interpolate missing hours; retain the 18-of-24 threshold and independent index statuses. Deduplicate exact physical timestamp before hourly averaging and prefer committed R2 over IngestDB. Preserve physical identity on output and mark unsafe identity/coverage conflicts partial or failed as the contract requires. The shared helper already implements the algorithm ([AQI helper](../../lib/aqi/aqi_levels.mjs#L371-L439)); reuse it with a smaller prepared input and visible output range.

The current IngestDB request explicitly sets `include_status:false`, and the normalised R2 read keeps value/identity but not `verification_status` ([RPC](../../workers/uk_aq_station_history/src/ingest_observations.mjs#L240-L247), [R2 normalization](../../workers/uk_aq_station_history/src/r2_observations.mjs#L138-L161)). No present implementation evidence shows verification status filtering in this station-history calculation. Any JSONgen source status / effective P-R verification projection must use the applicable canonical authority, and the recent seam must confirm which statuses are eligible under the existing source-quality contract before changing it; do not infer that unverified values are excluded today.

JSONgen's selected design is a separate private TEST bucket, `uk-aq-chart-history-json-test`, under `managed/jsongen/v1/`, with paired immutable monthly observation and AQI gzip JSON identified by the same UUID pubID. GitHub Actions prepares AQI from the shared algorithm and authenticated canonical v3 observation source; a small selector publishes only a complete matching pair. PubID discovery is approximately every five minutes; immutable files can be reused while the pubID is unchanged. This removes request-time historical Parquet decoding/observation preparation and historical AQI calculation from the station-history serving path **if** chart serving actually selects the publication. The existing opt-in prototype may still calculate AQI from decompressed JSON on request, so its CPU result does not establish savings from the future precomputed path ([pilot Worker](../../workers/uk_aq_compressed_chart_history/worker.mjs#L73-L95), [future contract](https://github.com/TEST-uk-aq/uk-aq-system-docs/blob/main/system_docs/station_charts/compressed_history_json_precomputed_aqi_test_contract.md)). The managed publisher and default chart integration are not yet active; `selectManagedPublications()` remains disabled ([control](../../scripts/jsongen/control.mjs#L102), [JSONgen contract](https://github.com/TEST-uk-aq/uk-aq-system-docs/blob/main/system_docs/station_charts/compressed_history_json_verified_writer_regeneration_contract.md)).

The simplest future serving model is: pin the selected pubID for each month; serve its matching precomputed observations and AQI for committed coverage, including the current month's **committed** portion only when an accepted open-month seam policy exists; query IngestDB for the short recent tail; merge at exact physical timestamp with committed R2/derived canonical rows first; calculate AQI only for recent tail endpoints with up to 23 preceding authenticated canonical observation hours, which may come from the selected current/previous monthly JSON. Never double count the boundary hour or reset PM context at a month/continuity boundary. A new committed Prune publication can supersede ingest rows, and a later Integrity correction may change adjacent-month PM AQI through `t+23h`; both monthly publications must remain paired/versioned and the old valid JSON remains visible until the replacement is selected and discovered. No extra freshness bus, fallback Parquet reader or second AQI algorithm is needed for this scenario. **Current/open-month JSON plus ingest stitching is not yet authorised by the active future contract**; it needs the separately recorded seam decision and targeted structural checks before implementation ([station-history contract](https://github.com/TEST-uk-aq/uk-aq-system-docs/blob/main/system_docs/aqi-levels/station-history-contract.md), [JSONgen contract](https://github.com/TEST-uk-aq/uk-aq-system-docs/blob/main/system_docs/station_charts/compressed_history_json_verified_writer_regeneration_contract.md)).

| Current default calculated route | Proposed selected JSONgen route |
| --- | --- |
| Private Worker reads canonical R2 pages and IngestDB, then merges and calculates historical and recent AQI for each cache miss. | Offline JSONgen prepares monthly canonical observations and AQI once per accepted publication; serving retrieves a pinned pair and calculates only recent IngestDB endpoints. |
| Up to seven visible days plus PM context per combined invocation; older chunks repeat context. | Historical immutable months reuse precomputed AQI; only recent tail plus 23 hours context needs helper work. |
| Short response cache helps complete payloads; sparse/partial results may miss cache. | PubID-keyed immutable files avoid repeated historical work; short live-tail freshness and explicit partial semantics remain. |
| R2 page/DB latency and Worker JSON parse/merge cost on misses. | Fewer canonical R2 page reads and less serving CPU; private derived R2 GET/transfer and manifest discovery still cost I/O and latency. |

## Cloudflare 10 ms question

The [TEST prototype contract](https://github.com/TEST-uk-aq/uk-aq-system-docs/blob/main/system_docs/station_charts/compressed_history_json_test_prototype_contract.md) and [presigned-ingestion amendment](https://github.com/TEST-uk-aq/uk-aq-system-docs/blob/main/system_docs/station_charts/compressed_history_json_presigned_ingestion_amendment.md) identify **Workers Free 10 ms CPU per HTTP request** as the intended budget. Workers Paid permits materially higher CPU limits (normally a larger configured/default request limit); `wrangler.toml` here does not specify a CPU limit ([config](../../workers/uk_aq_station_history/wrangler.toml)). Neither the Cloudflare account plan nor the effective Worker limit could be inspected. Requests at 20–53 ms CPU with no `exceededCpu` are consistent with a higher effective limit, but do **not** establish Paid status. CPU time is execution, excluding idle I/O wait; wall time may be much larger. Sampling, attribution and millisecond rounding may move near-10-ms values, but cannot plausibly explain a 53-ms reading under a strictly enforced 10-ms limit on that same invocation. Check the account's Workers plan, effective script CPU setting/usage model, deployment version during the export, and raw invocation `cpuTime`/`wallTime`/`outcome` fields together. The absence of `exceededCpu` in 1,297 exported invocations means no sampled reported CPU-limit termination, not that the 10-ms Free target was met.

## Remaining uncertainties

- The effective values of the calculated-AQI, validation mode/sample percentage and continuity flags, and any deployment change during the export; GitHub workflow fallback values do not answer this.
- The Cloudflare account plan and effective script CPU limit; the checked-in Wrangler file alone does not answer this.
- Raw row counts, R2 page counts, pollutant mix, cache hit/miss distribution, completeness and source modes behind the supplied median differences. No precise per-stage CPU attribution is available without targeted telemetry.
- Which error codes caused the 166 HTTP 502s and whether any were overlap conflicts, IngestDB failures or R2 failures. The validation warnings are explained by legacy comparison semantics but are not evidence of the 502 cause.
- Whether `include_status:false` and current R2 row projection correctly preserve the required source-quality/verification semantics for every recent connector. Confirm at the existing canonical/ingest contract boundary before any behavioural change.
