## 1. Executive summary

Significant contract-required parity gaps exist in **generic fixed-v3**. **Five confirmed code discrepancies** (three P1, two P2), **one probable P2 discrepancy**, and **two unresolved operational questions** are recorded below. There is no confirmed P0. The most immediate defects are loss of authenticated 404 evidence at the detector-to-planner boundary and a second, independent all-pollutant admission gate. A further detector omission can leave a missing selected pollutant child undiscovered under an existing connector.

This comparison does **not** equate v2 and v3 storage. V3's `history/v3/observations`, `_index_v3` exact leaves, aligned shards, non-empty exact scopes, transition fingerprint and publication graph are intentional. The [generation contract](https://github.com/TEST-uk-aq/uk-aq-system-docs/blob/11a0623bb8c82a58f9a03ae561cbc0269d255af9/system_docs/r2_history/observation_history_v3_side_by_side_generation_contract.md#L25), [exact-leaf amendment](https://github.com/TEST-uk-aq/uk-aq-system-docs/blob/11a0623bb8c82a58f9a03ae561cbc0269d255af9/system_docs/r2_history/observation_history_index_v3_exact_leaf_amendment.md#L34), [transition amendment](https://github.com/TEST-uk-aq/uk-aq-system-docs/blob/11a0623bb8c82a58f9a03ae561cbc0269d255af9/system_docs/r2_history/observation_history_index_v3_transition_modes_amendment.md#L145), and [APPLY safety contract](https://github.com/TEST-uk-aq/uk-aq-system-docs/blob/11a0623bb8c82a58f9a03ae561cbc0269d255af9/system_docs/r2_history/integrity_apply_safety_contract.md#L236) require those differences.

## 2. Immediate WAQN failure

The TEST WAQN connector 9, v3, 01–31 December 2025 incident reports 39 required files, 37 present, authenticated 404 for `NTH1_2025.RData` and `SWA5_2025.RData`, about 39,000 extracted rows, 31 missing observation days, no proposed repair, no R2 mutation and failed final verification. The count `required_source_files_incomplete:37+0/39` has a precise code explanation:

1. V3 acquisition records 404 and missing-column windows in its run context; the per-partition producer emits `required_source_file_count`, `successful_source_file_count`, `source_unavailable_file_keys`, `source_unavailable_scopes` and `comparison_scope="source_available_timestamp_windows"` ([v3 producer](https://github.com/TEST-uk-aq/uk-aq-ops/blob/142c6b27f447464b00596cb5f8982bce7a29da4b/scripts/uk-aq-history-integrity/bin/uk-aq-history-integrity-sos-light-v3_impl.py#L16318)).
2. Connector/day structural gaps call `source_evidence_for_connector_day()`, which passes producer output through `_v2_observation_repair_source_evidence_summary()` ([v3 detector](https://github.com/TEST-uk-aq/uk-aq-ops/blob/142c6b27f447464b00596cb5f8982bce7a29da4b/scripts/uk-aq-history-integrity/bin/uk-aq-history-integrity-sos-light-v3_impl.py#L12741)). That summary retains the two counts but discards `source_unavailable_file_keys` and `comparison_scope` ([v3 summary](https://github.com/TEST-uk-aq/uk-aq-ops/blob/142c6b27f447464b00596cb5f8982bce7a29da4b/scripts/uk-aq-history-integrity/bin/uk-aq-history-integrity-sos-light-v3_impl.py#L12566)). The lost fields are not restored on `source_evidence_by_pollutant`.
3. The v3 generic completeness check counts absent keys **only** when `comparison_scope` has that value, so it computes `37+0/39` and rejects the candidate ([v3 check](https://github.com/TEST-uk-aq/uk-aq-ops/blob/142c6b27f447464b00596cb5f8982bce7a29da4b/scripts/uk-aq-history-integrity/bin/uk-aq-history-integrity-sos-light-v3_impl.py#L18880)). The connector-wide planner also requires **every** requested pollutant to pass, instead of admitting independently repairable pollutants ([v3 planner](https://github.com/TEST-uk-aq/uk-aq-ops/blob/142c6b27f447464b00596cb5f8982bce7a29da4b/scripts/uk-aq-history-integrity/bin/uk-aq-history-integrity-sos-light-v3_impl.py#L19180)). V2 uses per-pollutant exact present/404 file sets and binding availability, then retains admitted pollutants independently ([v2 eligibility](https://github.com/TEST-uk-aq/uk-aq-ops/blob/142c6b27f447464b00596cb5f8982bce7a29da4b/scripts/uk-aq-history-integrity/bin/uk-aq-history-integrity_impl.py#L18170), [v2 planner](https://github.com/TEST-uk-aq/uk-aq-ops/blob/142c6b27f447464b00596cb5f8982bce7a29da4b/scripts/uk-aq-history-integrity/bin/uk-aq-history-integrity_impl.py#L18400)).

Thus the supplied `37+0/39` string confirms the **summary-loss path** as the immediate block. It does not prove what subsequent gates would have done after that block. For pollutant-specific gaps attached to an **existing** partition, v3 attaches fuller `source_partition_evidence` directly ([v3 detector](https://github.com/TEST-uk-aq/uk-aq-ops/blob/142c6b27f447464b00596cb5f8982bce7a29da4b/scripts/uk-aq-history-integrity/bin/uk-aq-history-integrity-sos-light-v3_impl.py#L13245)); those can escape this precise summary loss. Connector-wide gaps and any fallback to the reduced `source_resolution_by_pollutant` do not. Missing selected pollutant children under an otherwise populated connector have another detector omission (F3).

**Minimum likely correction:** carry complete, explicit present/404/column/window evidence through the v3 detector summary; validate disjoint exact required/present/404 sets, mandatory present metadata, selected binding and available/unavailable windows against the run context; and make structural-gap admission pollutant independent. Merely adding two fields to the summary would make the numeric check pass but would still leave the all-pollutant gate and weak cardinality-only classification. Preserve final-target reconstruction from source plus pinned rows, ratified-status non-regression, v10 Python/Node source authentication, exact selected-prefix tombstones, v3 graph/index publication, lock, backup currentness, readback and final verification. The [RData contract](https://github.com/TEST-uk-aq/uk-aq-system-docs/blob/11a0623bb8c82a58f9a03ae561cbc0269d255af9/system_docs/r2_history/official_network_rdata_historical_integrity_contract.md#L226) explicitly says a 404 is source unavailability, not deletion authority.
