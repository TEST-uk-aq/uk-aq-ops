## Schema/function compatibility

Ops `markCandidateAndConnectorGateComplete` (`workers/uk_aq_prune_daily/phase_b_history_r2.mjs:2394-2402`) sends `dayUtc, connectorId, runId, writerGitSha, JSON.stringify(outbox.evidence), Buffer|null` as `$1::date, $2::integer, $3::uuid, $4::text, $5::jsonb, $6::bytea`. This exactly matches `uk_aq_ops.insert_prune_jsongen_gate_acceptance(date, integer, uuid, text, jsonb, bytea)` in `schemas/migrations/20261017_001_ingest_prune_jsongen_gate_acceptance_outbox.sql`. Runtime run IDs are UUIDs; candidate and gate store their text form and the SQL function compares them to `p_run_id::text`. Phase B requires a lowercase 40-character writer Git SHA before work.

`scripts/jsongen/prune-outbox.mjs` emits the JSONB keys selected by the function: connector-manifest byte digest/size; pending disposition, intent, bucket, object key and compressed/uncompressed byte identities; original status provenance; and final evidence state. Ops and SQL enumerate the same six dispositions. Missing pending fields are `null` in the unattempted/failure path and satisfy the table's paired-null constraints. `prune-signed-upload.mjs` validates the exact derived key, bucket, intent and digest/size fields before its conditional PUT. A 2xx PUT is still `put_acknowledged_unverified`.

The SQL function takes source hash/version/row count, original manifest key/hash, row/file/byte counts, completion timestamp/source and READY marker from **locked database rows**, rather than trusting caller JSON. Its bytea checks require UTF-8 JSON object bytes with schema version 1, the exact final-preparation kind, acknowledged pending upload and connector-manifest byte identity. It also compares environment, index generation, writer/run/attempt/Git SHA, connector/day and source/manifest identities against the accepted gate. Ops supplies those fields in matching shapes; JSONB `->>` converts its numeric connector and source counts to the text compared with typed row values. `not_captured` sends null bytea; `prepared_unverified` sends the exact canonical JSON `Buffer`, bounded to 1,048,576 bytes. The generated SQL SHA-256 is over stored bytea, separate from semantic content/manifest hashes.

The migration table/function and `schemas/ingest_db/main_db_dualwrite_bootstrap.sql` canonical definitions agree; the bootstrap table uses `IF NOT EXISTS`. Existing bootstrap broad grants/default privileges for `service_role` are followed by an explicit revoke of all direct DML on the new outbox and a SELECT-only grant. EXECUTE is granted to `service_role` and retained by the owner. No incompatible field, cast, null pairing or constraint was found for the inspected well-formed Ops path. Actual target PostgreSQL version and application of the migration were **not** checked; the schema uses built-in `sha256(bytea)` and `txid_current()`.

## Protected transaction, XID proof and savepoint

The validated complete v3 run-finalizer result precedes original evidence preparation (`phase_b_history_r2.mjs:4380-4456`), which precedes the protected transaction. `markCandidateAndConnectorGateComplete` performs one `BEGIN`; the candidate UPDATE requires the exact day, connector, original run, `in_progress`, expected row count and null prior error. It must return exactly one database row (`:2239-2301`). The gate UPSERT also returns exactly one database row (`workers/shared/uk_aq_connector_day_gate.mjs:178-258`). Before any savepoint, `assertOriginalCandidateGateCompletion` compares returned source hash/version/count, manifest key/hash, counts, completion source/time, run and READY identity with the intended publication (`phase_b_history_r2.mjs:2304-2334`). A mismatch throws and rolls back. The optional function runs on that same client after the mandatory checks and before COMMIT. Outbox state is absent from deletion eligibility. READY-to-CONSUMED and gate-only-unproven recovery remain separate (`phase_b_history_r2.mjs:4600-4622`).

The SECURITY DEFINER function uses schema-qualified tables and `pg_catalog` search path. It locks candidate then gate, matching Ops write order, and compares each selected tuple's `xmin` (32-bit transaction ID) to the low 32 bits of `txid_current()`. A candidate UPDATE and gate INSERT/UPSERT produce versions in the current top-level transaction; `SELECT FOR UPDATE` locks but does not replace `xmin`. Ops performs both writes before the optional savepoint. A stale gate row from another transaction cannot pass the XID comparison. At higher isolation or on a deadlock/serialization failure the transaction may abort, which remains fail-closed. This is PostgreSQL-local **same-transaction** evidence. It cannot by itself establish the candidate's previous `in_progress` state, exactly-one update, external R2 finalization or writer process identity. Ops checks the first two. A principal with permission to update both existing rows and execute the function could construct a different same-XID transaction, so trusted caller identity and grants are part of the acceptance boundary.

The savepoint encloses only the optional insert (`phase_b_history_r2.mjs:2391-2423`). Recoverable evidence errors are SQLSTATE classes 22/23, permission denial `42501`, missing function/table `42883`/`42P01`, and three specifically named evidence-related `P0001` messages. Successful `ROLLBACK TO SAVEPOINT` and `RELEASE` precede committing the valid gate. Duplicate `23505` is `outbox_unresolved`, not an UPSERT or adoption. The function's candidate/gate transaction mismatch `P0001`, connection/transaction errors, cancellation and statement timeout are not reclassified as optional. Failed savepoint recovery reaches the outer rollback; no successful gate is reported. A missing `uk_aq_ops` schema is not classified optional, but mandatory candidate/gate tables also require that schema. No unsafe error classification was found. `outbox_missing` is a diagnostic, not a discoverable durable event.

## Exact metadata and pending-source lineage

`scripts/jsongen/prune-original-metadata.mjs` copies already offered/read `.json` bodies into a transient per-runtime map through existing v3 PUT/readback adapters (`phase_b_history_r2.mjs:3740-3788, 3984-4030`); it adds no R2 GET or Parquet reread. Selected references include canonical connector and pollutant manifests, all published exact-v3 objects (shards, leaves and scoped roots), every affected day parent, aggregate ancestors and final latest-global index. The shared canonical publisher returns `verified: true, durable: true` after exact readback/durability (`uk_aq_observation_history_operational_writer_v3.mjs:785-811, 1221-1242, 1273-1296`). The exact-v3 scheduler likewise returns those flags (`uk_aq_observation_history_index_v3.mjs:2810-2850, 2913-2922`); the run finalizer retains validated day, aggregate and latest references. Missing flags produce `not_captured`; none are fabricated.

The snapshot checks original byte length and SHA-256 against each verified reference, deduplicates equal key identities and rejects conflicting references. It stores exact body bytes by value, not parsed-object reserialization, because canonical JSON keys may later be replaced. A later generation's bytes fail the reference hash check. It never treats absent bytes as an empty publication. The early PENDING description retains frozen source identity, complete pollutant partitions, physical timeseries/day membership, effective P/R/null counts, original gzip/NDJSON hashes and honest `original_source_status_unavailable` provenance. Signed intent and conditional PUT bind the same compressed/uncompressed scope; private independent PENDING readback is still outstanding. The final preparation binds run/attempt, connector/day, source identity, child content hash/count/status and validated batch, but still says `precommit_prepared_unverified` and does not assert gate commit. Canonical P/R/null is not modified.

The snapshot targets the original connector lineage and affected batch parents. An independent verifier must decode retained bytes and check pollutant/physical membership, exact leaf/shard/root links, day/aggregate/global links, source-to-final scope and status before authenticating original publication. It need not copy every unrelated sibling connector or historical latest entry simply to assert one connector's lineage. Current `_index_v3/timeseries_binding`, source precedence and canonical status are a **separate Stage 3B** authority check. Integrity may later supersede the current canonical generation without rewriting the historical outbox.

Capture is bounded to 8 MiB transient raw bytes, 4,096 JSON objects and 1 MiB/object. Above 786,432 selected raw bytes, base64 alone reaches the database's 1 MiB field; the complete envelope is checked again. Missing/conflicting data or overflow yields `not_captured` and no final bytea if the optional outbox insert succeeds. No essential object is silently omitted to fit. The 8 MiB map is **not** a peak-memory limit: R2 bodies, copied Buffers, base64 strings, the object graph and serialized envelope can coexist. No real TEST size, peak memory or latency measurement exists. Over-limit scopes need a separately reviewed immutable external exact-byte snapshot with verified retention before an outbox reference; that pipeline is not implemented.
