## 2. Structural viability and precise boundary

The [current shared builder](https://github.com/TEST-uk-aq/uk-aq-ops/blob/fad44fecb0a33cd869945d74f69099850ac362fc/workers/shared/uk_aq_observation_history_exact_leaf_index_v3.mjs) declares exact schema 1 and emits `buildAlignedSourceShard()`, `buildAlignedSourceManifest()`, `buildExactLeaf()` and `buildExactScopedManifest()`. The latter two pin `source_aligned_child` and `source_aligned_scoped_manifest`. Both representations are publication objects. Removing fields alone would remove proof and break consumers.

The [exact reader](https://github.com/TEST-uk-aq/uk-aq-ops/blob/fad44fecb0a33cd869945d74f69099850ac362fc/workers/shared/uk_aq_observation_history_exact_leaf_reader_v3.mjs) validates those descriptor identities, without fetching aligned bodies on its normal chart path. It currently accepts exact schema 1, supports physical schemas 3 and 4, and uses private **cursor schema 3**. Exact-index schema 2 must not be confused with physical schema 4, logical hash v2 or cursor v3. Earlier pre-overlay cursor-v2 descriptions are not the current implementation baseline.

The [target writer](https://github.com/TEST-uk-aq/uk-aq-ops/blob/fad44fecb0a33cd869945d74f69099850ac362fc/workers/shared/uk_aq_observation_history_target_writer.mjs) already has actual-footer validation and complete-segment checking. This establishes a route to direct proof; it does not establish that a new verifier exists. Its inspected layout/rebuild implementation is schema-3-specific. Reader support for schema 4 does not prove that this inspector can rebuild every schema-4 scope.

Preserve the single `UK_AQ_R2_HISTORY_VERSION` generation selector, canonical v3 roots, logical v2 observation semantics, current `timeseries-aligned-v2` layout and 1,024-row cap. The word “aligned” in that physical layout name does not require retaining a duplicate `_aligned` index forever, and must not be renamed merely to remove that index.

The accepted base contract already supports direct canonical prerequisites, complete scope reconciliation and unchanged-child stability. Its `Child identity, scoped reconciliation and targeted finalisation` section explicitly keeps the whole-DCP canonical identity out of unchanged leaf bodies. These provisions support Option B in principle; they do not settle the new exact format or supersede Contract A's explicit gate. Do not claim that active prose universally mandates an `_aligned` tree: the current schema and its proof consumers do, while the exact-only replacement still lacks accepted detailed authority.

## 3. Conditional implementation design

After the handover is accepted, change shared code once and coordinate its consumers. No new service, catalogue, canonical witness, event ledger, packed record format, environment selector or backup domain is proposed.

1. Authenticate and pin the selected canonical root/year/month/day/connector/pollutant chain, including complete agreeing child aliases. Check the actual pollutant body key/size/SHA, `manifest_hash`, DCP identity, positive count, versioned logical hash and full per-file and per-timeseries counts.
2. Produce a distinguishable exact-only parent/leaf format. The parent directly pins that canonical descriptor and the complete leaf map; leaves retain only their own physical coverage, required file descriptors and exact ranges. New-schema records do not use aligned objects as authority. Existing schema-1 validation remains intact.
3. Compare the complete canonical member set with the entire exact parent map and leaf set; reconcile per-series/per-file/total counts, bounds, all groups, ordering and physical membership. Authenticate actual file SHA/size and validate row-group/range evidence independently of the index emitter. Use trusted writer evidence only with an explicitly accepted provenance and lifetime; otherwise inspect the pinned files offline. Preserve independent full-decode logical checks wherever existing writer/migration/recovery contracts require them.
4. Distinguish scheduling prerequisites from content dependencies. Canonical files/manifests and verified direct proof precede leaves; verified leaves precede selection; aggregate/latest/run completion retain their accepted order and exact readback. Root-to-DCP proof for a new write must be established against the completed new hierarchy before declaring final acceptance or a deletion gate; it cannot require a future root before bottom-up publication. Existing-scope conversion instead pins the already completed hierarchy under exclusion.
5. Deploy explicit dual-format validators/readers first. Bind exact format and scope selector/leaf identities to discovery, caches and private cursors. Unsupported or mixed authority fails closed; an error or 404 never chooses another format. Keep the same cold request chain, rather than add a root walk or Parquet inspection to charts.

Important unresolved selection detail: overwriting current deterministic leaf keys before switching the parent can invalidate the old parent. Updating `latest` last does not prevent this because the scoped manifest is the actual selector. The accepted contract must choose deterministic non-colliding new-format leaf keys and define replacement/retry semantics. Immutable or revision-qualified leaves can preserve selector coherence, but key derivation, body-hash self-reference avoidance, byte stability and retained-object capacity must be specified first. No particular key or kind is selected by this report.

The unchanged bounded reader envelope includes ≤24 hours per low-level request, one segment/≤1,024 rows per invocation, no runtime footer discovery or full-file scan, SHA/size/current required ETag and conditional ranges. Current implementation limits include four discovery index objects/8 MiB, two range reads/8 MiB, and a 12,288-character cursor ceiling. Station History retains a shared 16-page/5,000 accepted-R2-row invocation budget, continuity, R2/recent seam precedence, previous-23-hour PM context and existing DAQI/EAQI/status behavior. Preserve the Workers Free station-history CPU limit of 10 ms and measure headroom per actual Worker.

## 5. Conversion and rollback procedure — design only

No converter was implemented or executed. No executable conversion command exists for the proposed format; running an old full migration is not a substitute. After contract acceptance and code review, a separately authorised converter should:

1. Use existing environment configuration and selected v3 authority. Select a deterministic sorted bounded list of DCP scopes from authenticated canonical membership; persist a finite scope/object/byte budget. Do not scan/rewrite all Parquet or build a full second index.
2. Under the existing shared observations-operation lock, pin canonical root and full selected chain, exact original selector bytes/size/SHA, actual file identities, builder/profile/schema identity and the batch budget. Preserve source-backed recovery material. Reject incomplete or contradictory inputs before publication.
3. Inspect/reuse accepted physical layout evidence and build only the selected scope's new leaves and selector. Record exact prepared bytes, complete proof result, object dependencies and predicted peak capacity before writes. No canonical Parquet is rewritten for index conversion.
4. Publish only non-conflicting verified new dependencies. GET-verify exact bytes and durable file identity, then switch the scoped selector through the accepted old-identity guard. Read back and verify the selected complete scope, then update affected compact latest/run completion. Preserve old aligned objects and necessary schema-1 evidence. No step automatically retires them.
5. Record idempotent progress such as prepared/dependencies-verified/selector-selected/finalised with exact identities. These are proposed conversion evidence states, not a new global writer ledger. Stop on lock loss, source change, budget exhaustion or mismatch. Restart authenticates prepared bytes and current objects before reuse; existence alone proves nothing. A selected-but-unfinalised scope is reconciled before beginning another batch.
6. Reacquire and revalidate current authority for each later bounded batch. Already selected scopes are not silently regenerated against changed inputs. Report changed, skipped-current, blocked and incomplete scopes with exact evidence and remaining capacity.

The contract must specify the selected-but-unfinalised recovery case and how existing compact latest/guard consumers reconcile it; preserving the bottom-up hierarchy alone does not make multiple mutable objects transactional. Concurrent chart reads may fail closed on an independently advancing canonical source, but must never consume a mixed unproved authority.

Rollback before activation is removal/reversion of code changes through a reviewed release; no R2 operation is needed. After a scope switch, retain dual-format readers until current data are proved readable. Restoring the old selector is valid only if its canonical source and every retained file/leaf/aligned identity still match current accepted canonical data. If writers advanced, rebuild schema 1 from **current** canonical material, or perform separately authorised accepted recovery. Never restore a stale selector or advertise stale v2 as a complete rollback. Eventual aligned-object retirement is a separate explicitly authorised stage, with its own acceptance and retention policy; no bulk-delete implementation is included.

## 6. Storage, object and operation model

Operator-supplied 31 October LIVE totals are context only: `_index_v3` ≈4.445 GiB; `history/v3` ≈3.215 GiB; `_index_v2` ≈54.530 MiB; `history/v2` ≈493.900 MiB. No LIVE repository or R2 inventory was inspected. Do not combine that newer aggregate with an old aligned subset and present the result as a measurement.

The earlier same-population model is `4.420 − 1.523 = 2.897 GiB`, before replacement metadata. Gross eventual removable aligned bytes are ≈34.46% of that historical complete index. Let `delta_exact` be net replacement parent/leaf bytes and `R` retained mixed-format/rollback bytes not already counted. After separately authorised retirement, estimated steady state is `2.897 GiB + delta_exact + R`; savings are `1.523 GiB − delta_exact − R`. Retaining every aligned object means those 1.523 GiB have **not** been reclaimed.

For `D` non-empty scopes and `A = sum(distinct floor(timeseries_id / 1000) shard ranges per scope)`, current aligned object count is `A + D`. If `L` exact leaves remain independently addressable, exact-only steady-state removes those `A + D` objects after authorised retirement, adjusted for any retained legacy scopes/revisions. It does not remove `L` exact objects or the `D` exact scoped selectors. Actual `A`, `D`, `L`, leaf-size changes and request counts were not measured, so no numeric object saving is asserted.

During this implementation and no-delete conversion phase, old aligned bytes/count remain. Peak is approximately `current total + new batch leaves + retained old exact revisions/selectors + prepared operational evidence + changed latest metadata`; unchanged canonical files add zero conversion bytes. Released local staging is not an R2 saving. The operator must supply an actual capacity allowance and current authorised TEST inventory before executing batches. Stop before a batch whose peak exceeds the allowance; do not assume room for another full index. Later writers avoiding aligned publication reduce future growth even while retained old aligned objects consume space.

Class A PUT/LIST work can fall by avoided aligned shards/manifests, plus their readback/verification Class B GETs. Direct canonical authentication/layout inspection still costs work, and no guaranteed net count or speedup is known. Class B HEAD/GET and conditional range accounting must include retries and verification. Since charts already skip aligned GETs, do not claim automatic chart-network savings. Canonical backup coverage, JSONgen storage and old v2 bytes are not credited as savings.
