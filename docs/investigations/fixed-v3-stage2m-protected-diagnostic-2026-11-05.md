## Protected sequence and bounded handoff

1. The unchanged coordinator performs the request-wide IngestDB boundary, acquires the existing single observations-operation PostgreSQL advisory lock, authenticates the complete checkpoint, runs existing backup readiness and locked checkpoint/current-root equality, and pins that baseline. Diagnostic dispatch is an early return **after these gates and before** normal preflight, SQLite run creation, source acquisition, DETECT/PROPOSE, repair planning or APPLY.
2. The outer invocation creates a unique private temporary workspace using its existing tmp directory. Inside the retained lock, Python writes a small bootstrap containing only accepted checkpoint/baseline/run/nonce and explicit boundary-derived DCP selection. It contains no credentials or private assertion descriptor. The local-only preparation worker receives no channel metadata or inherited fd and remains in the existing protected process group.
3. Before registry parsing, the worker admits byte/JSON depth/token/string and registry cardinality limits. It traverses only the pinned canonical hierarchy, admits complete membership/compressed-byte budgets, and makes an exact complete unmasked run-local baseline snapshot plus compact latest. Symlinks, traversal, changed inode/times/size/SHA, extra/missing membership and checkpoint contradictions fail closed. The source baseline and exact checkpoint bytes are rechecked. This transient snapshot fits v1's private run-root references without placing preparation files in Dropbox or expanding the backup domain.
4. The worker calls `prepareSchema2PreparationV1()` and `validateSchema2PreparationV1()`. The full v1 record remains separate at `runState.schema2_preparation`, with no executable proposals or inventory transfer into `runState.objects`. A complete request/sidecar file is pinned by exact SHA/length. Control files retain the preparation JSON lexical limits and an **8 MiB** ceiling; outputs carry no duplicated source/physical bodies. Unsupported preparation is an explicit blocked diagnostic with zero current R2 discovery.
5. Python authenticates the full prepared-request SHA/length, then `OriginalIntegrityChannel.popen_diagnostic()` passes the existing Stage 2J fd exactly once to the exact read-only Node entry point. It cannot select normal APPLY or `--write-r2`, reuse the descriptor, send it to an unrelated process or reconnect. The child authenticates and unlinks the input before use. A standalone/copied-context invocation cannot reach current R2 authentication.
6. The child independently validates preparation and original snapshot provenance, calls unchanged `admitSchema2CurrentObjectsV1({ phase: "APPLY", ... })`, rechecks original local provenance and makes a final same-session assertion. Only a bounded GET adapter is exposed; it has no PUT/DELETE/publication methods. Native R2 configuration and credentials are reused without serialising them.
7. Success sends the existing bound channel-completion frame. Failure/uncertainty permanently closes the capability; cancellation and runtime expiry stop the child through the existing protected group lifecycle. The outer diagnostic-specific signal relay forwards SIGINT/SIGTERM to the holder and waits for its cleanup before temporary-directory removal. Ordinary schema-1 launcher behaviour is unchanged. There is no restart/resume, new session or persistent recovery protocol.

Stage 2K's only compatibility adjustment permits `:` in its otherwise safe run-ID filename grammar, because genuine coordinator IDs are `integrity:TEST:<timestamp>`. Separators, dots/traversal and unsafe characters remain rejected. Existing v1 contract identifiers, directory scheme, deterministic freeze, original/proposed meanings, body references, resource and independent validation rules are unchanged; no previously frozen record is upgraded.

## Authentication, output and supported limits

Stage 2L still owns current root/ancestor and compact-latest authentication; exact current predecessor selector bytes/size/SHA and genuine strong response ETags; complete schema-1 aligned/schema-2 immutable dependencies; independently inspected supported physical bytes; frozen prior/proposed separation; and final remote/local rechecks. Assertions reach the original retained PostgreSQL client via the same holder/supervisor/Python/Node channel, binding owner/run/nonce, stable backend PID, operation/child lifetimes, challenges and sequence. No independent PostgreSQL session is used for assertions.

Limits remain **16 affected DCPs, 64 whole selected scopes, 4,096 preparation objects, 16,384 edges**, the existing body/row/physical/memory limits including **1 GiB** estimated peak, and Stage 2L's **220 current objects / 440 bounded GETs**. Complete preparation and current graph must fit; this mode never silently narrows the checkpoint to make a small requested scope fit. The final wrapper assertion adds one call to L's maximum 1,010, remaining below the existing 1,024 lifetime ceiling. Any earlier consumption still fails closed on exhaustion.

Supported physical evidence remains schema 3 / `parquet-wasm-zstd-v3` / observation-content hash v1, with the admitted bounded ZSTD/Parquet/encoding profile and required runtime inspectors. Schema 4, unknown encodings, non-reproducible historical identities, missing/changed/weak-ETag state, absence/no-selector, new/empty/removal scopes, unsupported changed-source diagnostic requests and resource overflow remain blocked. Real TEST capacity/format fit was not inspected or measured.

Only compact JSON diagnostics are retained in the existing report directory as `<run_compact>-schema2-diagnostic.json`. Successful output is `diagnostic_authenticated`, not a repair or writer status. It includes bounded scope/object/GET counts, proof version, preparation fingerprint and original-session assertion diagnostics. All results state read-only, completed-call-only, non-reusable, repair/publication ineligible, no repair/writer finalisation, no source deletion and null mutation authority. Credentials, private channel descriptors, environment dumps, canonical freeze text and source/physical bodies are excluded. The v1 preparation, its private bodies and both handoffs remain transient scratch and are removed with the invocation.

Blocked/interrupted/cancelled/timeout output reports bounded known reasons and tri-state continuity: `false` only after asserted successful admission, `true` for explicit original-operation loss, and `null` where continuity is unconfirmed. An abrupt group death may leave only the prewritten `diagnostic_interrupted` record; unknown continuity is never upgraded to success. Precondition failures remain the normal bounded reports, explicitly marked diagnostic-only with continuity not asserted. A nonzero holder result downgrades any already-written authenticated result to `diagnostic_failed_cleanup`.
