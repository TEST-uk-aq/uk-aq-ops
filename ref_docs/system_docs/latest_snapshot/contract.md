# Latest snapshot behavioural contract

## Authority

This file is the authoritative behavioural contract for the latest-snapshot system.

Implementation files, worker-local READMEs, plans and archives MUST conform to this contract unless an intentional contract change is approved and documented.

## Purpose

The latest-snapshot system provides deterministic, cacheable website data representing the latest valid pollutant observation for each eligible timeseries.

It is a current-state product. It is not the authoritative raw observation record.

## Scope

### Public request matrix

- pollutants: `pm25`, `pm10`, `no2`;
- windows: `3h`, `6h`, `1d`, `7d`, `all`;
- network group: `all`;
- output contract: `v2`.

### Physical R2 matrix

- pollutants: `pm25`, `pm10`, `no2`;
- physical window: `all` only;
- network group: `all`;
- physical object count: three.

The public request matrix and physical R2 matrix are intentionally different. Finite windows are derived by the R2 API Worker and are not separately stored products.

## Definitions

### Raw observation

A source observation received by the wider UK AQ ingestion system. Raw observations may include sentinel, invalid, outlier or otherwise unusable values and remain part of source history.

### Valid current pollutant value

A value eligible to become the latest public current value for a pollutant timeseries.

For the current matrix, the value MUST:

1. be numeric and finite;
2. be greater than or equal to `0`;
3. satisfy any existing pollutant-specific upper bound.

The current upper-bound behaviour is:

- PM2.5: maximum `500`;
- PM10: maximum `600`;
- NO2: no additional upper bound in this component.

Zero is valid. A negative pollutant value, including `-99`, is not valid current state.

### Latest valid state

The single retained latest valid observation for one `(connector_id, timeseries_id)` identity.

### Physical snapshot

The stable, hash-gated R2 object generated by the Cloud Run builder for one pollutant with `window=all`.

### Finite public response

A request-time representation produced by filtering a physical `all` snapshot to `3h`, `6h`, `1d` or `7d` using each row's `last_value_at`.

### Durable R2 object

An object whose R2 copy remains authoritative for runtime behaviour. For the warm-cache amendment these objects are:

- latest state;
- the core metadata cache;
- the physical family manifest.

### Warm local cache

A disposable container-local copy of a durable R2 object and a validation sidecar. It may reduce R2 body downloads while a Cloud Run container remains warm, but it is not authoritative state, a backup or a recovery source.

### Run report

An optional timestamped diagnostic object under the configured `_runs` prefix. It is not a physical snapshot product and is not part of the manifest inventory.

## Required invariants

### Raw-data separation

- The observation publisher MUST continue publishing raw observations needed by raw observation consumers.
- The latest-snapshot system MUST use its dedicated Pub/Sub subscription and MUST NOT consume the raw writer's subscription.
- Latest-current-value eligibility MUST NOT prevent invalid or sentinel rows from reaching raw `observations`, `observs` or R2 observation history.
- Invalid current values MUST be rejected by this consumer, not removed from the shared raw stream.

### State identity and replacement

- State identity MUST remain `(connector_id, timeseries_id)`.
- A valid observation MUST create state when no state exists.
- A newer valid observation MUST replace older valid state.
- An older valid observation MUST NOT replace newer valid state.
- An invalid observation MUST NOT create or replace state.
- The previous valid state row MUST remain unchanged until a newer valid observation arrives.
- Existing same-timestamp valid-row tie-breaking using `ingested_at` MUST remain unchanged unless separately approved.

### Message acknowledgement

- Malformed messages MAY be acknowledged as malformed according to existing behaviour.
- Decoded valid and invalid observation messages MUST be acknowledged after successful state handling.
- A deliberately skipped invalid value is successfully handled and MUST NOT be left for endless redelivery.
- If state persistence fails, acknowledgement MUST NOT move ahead of the failed state handling.
- A local-cache write MUST NOT be treated as durable state persistence.

### State persistence

- State MUST remain at `latest_snapshots_state/v1/latest_state.json` unless an approved migration changes it.
- The state schema remains version `1`.
- State MUST contain only entries eligible to act as latest current values for the supported pollutant matrix.
- State writes SHOULD remain hash-gated.
- An R2 state write MUST succeed before its local cache entry is updated.

### Metadata eligibility and freshness

- Timeseries metadata must resolve through the core metadata cache.
- The timeseries must resolve to its station, connector, phenomenon and observed property as required by the v2 row contract.
- Public network identity must resolve through `station.network_id -> networks.id`.
- Missing required station or network metadata is counted and skipped.
- Networks with `public_display_enabled=false` are skipped.
- The existing station geography requirement remains in force.
- Connector-derived network fallbacks MUST NOT be introduced.
- The durable core metadata cache is a derived optimisation over the authoritative R2 core snapshot family and MUST NOT remain authoritative after a newer core snapshot is available.
- Before reusing `latest_snapshots_state/v1/core_metadata_cache_v2.json`, the builder MUST resolve the newest available core manifest under the configured core metadata prefix.
- The durable metadata cache MAY be reused only when it is within `UK_AQ_LATEST_SNAPSHOT_METADATA_REFRESH_SECONDS` **and** represents that newest available core manifest.
- `UK_AQ_LATEST_SNAPSHOT_METADATA_REFRESH_SECONDS` is a maximum cache age, not the sole freshness criterion.
- A cache whose `source_day_utc` differs from the newest available core-manifest day MUST be rebuilt before observation messages are consumed or acknowledged.
- A same-day core-manifest replacement or rerun that is newer than the cache generation time MUST also invalidate and rebuild the metadata cache.
- If the newest core manifest cannot be resolved, the builder MUST fail closed rather than consume observation messages using metadata that cannot be confirmed current.
- Local caching MUST NOT extend metadata freshness beyond either the TTL or the newest-core-manifest freshness rule.

### Observation time and window behaviour

- Persisted state uses `observed_at` as the retained valid observation timestamp.
- Public rows expose that timestamp as `last_value_at`.
- A newer invalid observation MUST NOT refresh the retained timestamp.
- The physical `window=all` object includes every metadata-eligible retained valid state row regardless of age.
- Finite cutoffs MUST use the start of the current UTC minute.
- A finite row is included when its parseable `last_value_at` is greater than or equal to the cutoff.
- A row with missing or unparseable `last_value_at` MUST be excluded from finite responses.
- Filtering MUST preserve the physical object's row order.

### Physical snapshot generation

The builder MUST:

- publish only `window=all` for each configured supported pollutant;
- use deterministic keys for `(network_group, pollutant, all)`;
- preserve the v2 top-level and row fields;
- sort each pollutant's rows using the existing ordering;
- derive the existing cursor for the physical payload;
- use stable JSON and SHA-256 hash gating;
- skip unchanged object writes;
- preserve a previous `all` manifest entry when that pollutant build fails and an entry exists.

`UK_AQ_LATEST_SNAPSHOT_WINDOWS` is not a builder configuration input. Public finite windows are owned by the R2 API Worker.

### Manifest

The manifest MUST describe physical stored products only.

For the current system:

- `matrix.pollutants` contains `pm25`, `pm10` and `no2`;
- `matrix.windows` contains only `all`;
- a fully successful build contains three snapshot entries;
- each entry points to a physical `window=all.json` object.

The manifest MUST NOT invent virtual entries for finite API responses.

An R2 manifest write MUST succeed before its local cache entry is updated.

### Warm local cache

When `UK_AQ_LATEST_SNAPSHOT_LOCAL_CACHE_ENABLED=true`:

- the default cache directory is `/tmp/uk-aq-latest-snapshot-cache`;
- cache filenames MUST be derived safely from the full R2 key rather than using the key as a filesystem path;
- each cached body MUST have a sidecar containing schema version, R2 key, R2 ETag and local SHA-256;
- the local body MUST parse as JSON and match the sidecar SHA-256 before reuse;
- the current R2 object MUST exist and its ETag MUST match the sidecar before reuse;
- a missing ETag means the local copy is not reusable and is not stored as a validated entry;
- missing, corrupt, mismatched or unvalidated local entries MUST fall back to the normal R2 GET path;
- R2 validation or GET failures MUST NOT be hidden by serving an unvalidated stale local copy;
- local writes MUST occur only after the corresponding R2 GET or PUT succeeds;
- local write failures MUST be logged and treated as cache warnings rather than durable-operation success or failure;
- local files MUST be written using temporary files and rename;
- deleting the container or every local cache file MUST require no migration or recovery action.

When `UK_AQ_LATEST_SNAPSHOT_LOCAL_CACHE_ENABLED=false`, durable objects MUST use the direct R2 path and all public and state behaviour MUST remain unchanged.

The warm cache applies only to:

- `latest_snapshots_state/v1/latest_state.json`;
- `latest_snapshots_state/v1/core_metadata_cache_v2.json`;
- `latest_snapshots/v2/manifest.json`.

It does not cache physical pollutant snapshot objects for the builder.

A validated local copy of `core_metadata_cache_v2.json` proves only that the local bytes match the durable metadata-cache object. It MUST NOT bypass the newest-core-manifest freshness check.

### Run-report policy

`UK_AQ_LATEST_SNAPSHOT_RUN_REPORTS_MODE` accepts only `all`, `failures` and `off`. An explicit unsupported value MUST fail clearly.

Resolution order is:

1. an explicitly configured new mode;
2. the legacy `UK_AQ_LATEST_SNAPSHOT_RUN_REPORTS_ENABLED` boolean when the new mode is absent;
3. default mode `failures` when neither is configured.

Legacy mapping is:

- `true` -> `all`;
- `false` -> `off`.

Mode behaviour is:

- `all`: write the existing run-report object for every completed run;
- `failures`: write a report for every completed manual run and every completed run with one or more failed matrix items, but not a successful scheduled run;
- `off`: do not write R2 run-report objects.

For every mode:

- the physical manifest remains governed by its existing rules;
- the structured `latest_snapshot_job_summary` log remains emitted for every completed build;
- run-report creation MUST NOT determine build success, state persistence, acknowledgement or manifest success;
- existing run-report schema and key naming remain unchanged for reports that are written;
- old `_runs` objects are not deleted by this policy.

Early failures before a completed build report exists remain represented by service error logs and normal failure status. This amendment does not create a separate exception-report object.

### R2 API Worker

For every accepted latest-snapshot request, the Worker MUST read the requested pollutant's physical `window=all` object.

For `window=all`, it MUST return the stored representation directly with the physical object ETag.

For a finite window, it MUST:

1. parse and validate the physical v2 payload;
2. apply the UTC-minute cutoff to `last_value_at`;
3. preserve row order;
4. set `window` to the requested label;
5. recalculate `count`;
6. recalculate `next_since` and `next_since_id` using the existing cursor meaning;
7. preserve all other top-level and row fields;
8. return `X-UK-AQ-Snapshot-Contract: v2`.

The Worker MUST fail closed on malformed physical payloads and MUST NOT fall back to old finite objects or v1.

### Finite response cache identity

A finite response can change solely because time passes.

Its ETag MUST therefore depend on:

- the physical source object ETag;
- the requested finite window;
- the effective UTC minute.

Matching `If-None-Match` requests MAY return `304`. The existing cache-control configuration remains in force.

### Public v2 compatibility

The current architecture MUST preserve:

- the `latest_snapshots/v2` prefix;
- the manifest path;
- query parameter names and accepted public values;
- the cache-proxy route;
- response field names and meanings;
- scalar network fields;
- connector provenance fields;
- `X-UK-AQ-Snapshot-Contract: v2`;
- fail-closed behaviour for non-v2 standard paths.

### Public cache-proxy access amendment

The browser-facing cache-proxy route:

```text
GET /api/aq/latest-snapshot
```

is session-free public read data under [`../cache_proxy/public-display-data-routes-contract.md`](../cache_proxy/public-display-data-routes-contract.md).

That amendment changes only the browser-facing cache-proxy access boundary. It MUST NOT:

- make the private latest-snapshot R2 API Worker public;
- remove `X-UK-AQ-Upstream-Auth` from the private upstream boundary;
- change latest-snapshot query, cache-key, ETag, response or validation semantics;
- make unrelated cache-proxy routes session-free.

The shared website cache-auth helper MUST recognise the contracted public route and MUST NOT initialise Turnstile/session merely to request it.

### Legacy current-reading retirement

The old Supabase current-reading path is retired. The following MUST NOT be active dependencies, compatibility fallbacks or recovery paths for Latest Snapshot:

```text
/api/aq/latest
uk_aq_latest                  Supabase Edge Function
uk_aq_public.uk_aq_latest_rpc database RPC
```

As of 18 August 2026 the LIVE Edge Function and database RPC are both retired. Reintroducing any part of this path requires an explicit contract change and normal TEST acceptance before promotion.

## Old finite objects

Old `window=3h.json`, `window=6h.json`, `window=1d.json` and `window=7d.json` objects may remain in R2 after cutover.

They are inert historical artefacts. They MUST NOT be updated, advertised in the current manifest, or used as fallbacks.

## Explicit non-goals

A Latest Snapshot change MUST NOT, unless separately approved:

- delete or rewrite raw observation history;
- change AQI or WHO calculations;
- change connector checkpoint semantics in another repository;
- add pollutants or public window labels;
- change station display-name formatting;
- change network assignment or visibility rules;
- change cache-proxy routes or authentication except for the explicitly approved session-free `/api/aq/latest-snapshot` browser-read amendment governed by `../cache_proxy/public-display-data-routes-contract.md`;
- change Cloud Scheduler cadence, service resources, concurrency or timeouts;
- refactor unrelated shared R2 code;
- treat `/tmp` as durable state or recovery evidence;
- delete existing `_runs` objects as part of the report-mode policy.

## Implementation status

The latest-valid state ordering, all-only physical snapshot architecture, ETag-validated warm local cache and failures-by-default run-report policy are implemented on TEST as of 17 July 2026.

Newest-core-manifest-aware metadata-cache freshness is accepted for implementation on TEST as of 15 August 2026. See [`decisions/0006-core-metadata-cache-follows-latest-core-snapshot.md`](decisions/0006-core-metadata-cache-follows-latest-core-snapshot.md).

## Contract-change rule

Changes to value eligibility, state identity, replacement ordering, durable authority, metadata freshness, warm-cache validation, run-report mode semantics, physical product ownership, finite-window semantics, v2 fields, cache identity or failure behaviour require:

1. an update to this contract;
2. an update or new decision record;
3. only the smallest structural or targeted deterministic check genuinely needed;
4. functional validation through normal TEST operation.
